# Android UDP lab 0.4: protected outbound exchange, no TUN

This increment adds INTERNET and ACCESS_NETWORK_STATE, a visible manual UDP lab launcher, a bound helper in VpnPreparationService, numeric endpoint validation and five new target-validation tests. Version is 0.4.0-udp-lab, versionCode 4. The existing consent screen and policy editor remain internal activities. No database or domain-policy changes, dependency additions, foreground session, TUN, routes, DNS interception or always-on support are introduced. Existing 13 forwarding tests passed as part of the successful Android workflow for prepared head 62c691766007c52e4d35925dfd399feced09bf82; the new increment has not been built or tested yet.

The user must supply a numeric IPv4/UDP Echo endpoint they control. There is no default endpoint. ALLOW sends only a fresh random 16-byte nonce, unencrypted, after checking current VPN preparation and a non-VPN active network. Each outbound socket must pass VpnService.protect and Network.bindSocket for that network, with broadcast disabled. Failures have no unprotected or alternate-network fallback. DENY returns before creating the UDP socket. The response must reproduce the nonce exactly. This is a request/reply transport test, not a persistent flow proxy, encryption tunnel, test of another app, proof of TUN routing or full-device protection.

The source address 10.0.0.2 and port 40000 are synthetic codec-envelope fixtures, NOT authenticated Android app attribution or the upstream source endpoint. The physical source address and ephemeral UDP port are assigned by the OS on the selected underlying network. No raw IP frame is sent to the Echo server; the forwarder sends only its UDP payload. Domain profiles/rules are deliberately not connected to the lab's separate allow/deny control. Endpoint validation is not a complete subnet-aware directed-broadcast classifier; the socket disables broadcast and target ownership remains the user's responsibility.

The helper is bound only while the lab activity is visible. Leaving the activity, cancellation, unbind, revoke or service destruction cancels work and closes the forwarder. Cancelling cannot recall an already transmitted datagram. No foreground service or active-VPN notification is claimed. No automatic probes, saved authorization booleans, traffic logs or telemetry are added. Input values survive activity recreation but do not automatically trigger a send.

Acceptance after CI: install with a compatible signature without deleting app data; verify old profiles/rules remain; reject invalid target input; open the existing system-consent screen and test cancellation/approval; return to the lab; run DENY and verify no datagram at your Echo server; run ALLOW and verify a single 16-byte request and matching response at both ends; stop the server and confirm a failure rather than a claimed policy block; test cancellation, leaving the screen, rotation and losing the underlying network. Verify other apps are not intercepted. UDP may be blocked by a network/firewall and Echo service setup is separate; do not send test probes to arbitrary third-party services.

The updated PR must rerun assembleDebug, all JVM tests and lintDebug. CI does not validate Android VPN preparation, socket protection, binding, permission/revoke or lifecycle behavior. Those require device testing. Real foreground/TUN integration remains gated on this test and on a narrow, explicitly authorized routing scope; no default route may be enabled based on this lab alone.
