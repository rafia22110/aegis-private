# 0.4 forwarding work: isolated UDP request/reply core

This commit adds Java source and 13 JUnit tests only. No Manifest, UI, database, permissions, dependencies, APK version or Android service behavior changes. The installed app remains the 0.3 preparation UI until a separately reviewed integration exists. This is not a complete 0.4 VPN delivery.

Ipv4UdpPacket parses and encodes unfragmented IPv4/UDP packets, checks exact IP and UDP lengths, validates the IPv4 checksum and any nonzero UDP checksum, and emits checksummed reply packets with reversed endpoints. Deliberate limits: 1500-byte packets, no IP options, TTL must be nonzero, no fragments, TCP, IPv6 or multicast, and both ports must be nonzero. The first-octet address check is not a substitute for subnet-aware broadcast or destination policy checks. UDP zero checksum on IPv4 is accepted as specified by RFC 768. The codec does not authenticate a source app.

UdpForwarder implements one outbound datagram and one reply per exchange using a new connected UDP socket. It is NOT a persistent UDP flow/NAT engine and cannot be used as a general QUIC, streaming or multi-reply DNS proxy. Source ports at the upstream endpoint are OS-assigned. Policy is checked before socket creation. DENY returns null; malformed input throws IllegalArgumentException; network/protection errors throw IOException. No network failure is reported as a policy block. An injected protector must succeed before connect/send; Android integration must supply VpnService.protect and appropriate underlying-network binding. There is no permissive fallback. The injected numeric-IP/port policy is intentionally not connected to LocalPolicy domain rules: no DNS/IP equivalence or app attribution is invented. Calls are limited to one active exchange; close closes the active socket and permanently rejects new requests. The receive timeout bounds the reply wait, not arbitrary blocking inside injected callbacks or every operation. Replies above the supported MTU fail instead of being silently truncated into valid packets.

13 JUnit tests cover codec/reply construction, malformed checksums, omitted IPv4 UDP checksum, fragments, truncation, payload bounds, denial, protector failure, policy exceptions, closed state, and real localhost UDP request/reply including an oversized reply. Loopback tests use an explicitly test-only protector returning true; they do not validate Android socket protection. Tests are added but have not been executed during preparation. CI must run assembleDebug, testDebugUnitTest and lintDebug. No default route or TUN is opened, no external test endpoint is contacted by the test suite, and no network protection is claimed.

Before service integration: validate a narrow destination policy and real Android socket protection; add stop/revoke and network-change tests, observability, concurrency/flow management, underlying-network handling and the foreground service lifecycle. Before broader routing: implement or integrate and validate TCP/IPv6, fragmentation/MTU handling and the required UDP flow semantics, and verify real allowed and denied traffic at an observable test endpoint. Never enable a whole-device route based on this unit alone.
